# 日次ログ

Claude Code の作業履歴から、その日の記録を 1 日 1 ファイルで積み上げる。
日報を手で書かなくても記録がたまることが目的なので、本人に質問せず、履歴だけから書き切る。

## 設定を探す

保存先はスキルの中には無い。ユーザーレベルの設定に書かれている。

- 探し先: `~/.claude/CLAUDE.md`、開いているフォルダの `CLAUDE.md`
- 書き方の例: `- 日次ログの保存先: <フォルダのパス>`

見つからなければ、対話中なら保存先を聞く。自動実行(プロンプトに `[daily-log:auto]` がある)なら、
何も書かずに「保存先の設定が見つからない」とだけ出力して終える。
保存先のフォルダの近くに `CLAUDE.md` があれば読み、表記のルール(常体・用語など)に合わせる。

## 対象の日を決める

スクリプトは `${CLAUDE_PLUGIN_ROOT}/scripts/collect.mjs`。

- 日付の指定があれば、その日だけ
- 指定がなければ、未作成の日をすべて:
  `node "${CLAUDE_PLUGIN_ROOT}/scripts/collect.mjs" pending --out <保存先>`
  (今日は含めない。直近 14 日まで遡る。もっと遡りたいと言われたら `--days` を増やす)

`<保存先>/YYYY-MM-DD.md` がすでにある日は書かない(同じ日を 2 回作らない)。
本人が「作り直して」と明示したときだけ上書きする。

## 1日分を書く

1. `node "${CLAUDE_PLUGIN_ROOT}/scripts/collect.mjs" digest --date YYYY-MM-DD` で材料を出す
2. セッションが 0 件なら、その日はファイルを作らない
3. 次の形で `<保存先>/YYYY-MM-DD.md` を書く

```markdown
---
日付: YYYY-MM-DD
テーマ:
  - <その日の主なテーマ。2〜4個、短い名詞句>
セッション数: <ダイジェスト見出しの件数>
---

# YYYY-MM-DD

## やったこと
- <テーマごとに1〜3行。何をして、どうなったか(マージした・途中で止めた・方針を決めた)>

## 気づき・学び
- <やり方・判断・ツールについて、次に効きそうなこと。つまずきと、その乗り越え方>

## 繰り返し出てきた作業
- <同じ日の中で何度も出てきた作業や、直近の日次ログにも出ている作業。スキル化・自動化の候補になる>
```

### 書き方

- 材料はダイジェストに書かれていることだけ。推測で話を足さない。感情や理由は、本人がプロンプトで言っていれば書く
- 「気づき・学び」は、本人の言葉・判断と、うまくいった/いかなかったことから拾う。Claude の説明を言い換えただけのものは入れない。無ければ「特になし」
- 「繰り返し出てきた作業」は、保存先にある直近 7 日の日次ログも読んで見比べる。無ければ「特になし」
- 1 ファイルは長くても 40 行程度。セッションの一覧を写さず、テーマで束ねる
- 自分のプロジェクト名・リポジトリ名・ツール名は書いてよい(あとで横断して読むときの手がかりになる)

### 書かないこと

日次ログはあとで別の用途(ブログのネタ・ふりかえり)に回すので、業務の具体的な情報は残さない。

- 勤務先・取引先・施設などの固有名、人名(本人以外)
- 社内の数字(売上・人数・金額・件数など)、顧客や利用者に関する情報
- パスワード・API キー・トークン・メールアドレス・URL のクエリ文字列

業務の話は「何を学んだか」の粒度に言い換える。
例:「〇〇施設の△△さんと××の件で打ち合わせ」→「現場の人と要件をすり合わせた。先に画面を見せると話が早い」

## 終わったら

作った日付と、各日のテーマを 1 行ずつ報告する。スキップした日(既存・0 件)があれば、それも一言添える。
