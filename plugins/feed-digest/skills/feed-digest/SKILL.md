# フィードダイジェスト

購読しているブログの新着を、読むかどうか決めやすい形にまとめる。
全記事の本文は保存しない。本人がダイジェストでチェックした記事だけ本文を残す(積読と保存先の散らかりを避けるため)。

## 設定を探す

保存先はスキルの中には無い。ユーザーレベルの設定に書かれている。

- 探し先: `~/.claude/CLAUDE.md`、開いているフォルダの `CLAUDE.md`
- 書き方の例: `- フィードダイジェストの保存先: <フォルダのパス>`

購読するフィードは `<保存先>/feeds.json` に書かれている。

```json
{
  "feeds": [
    { "id": "example-blog", "name": "Example Blog", "url": "https://example.com/feed.xml", "perspective": "実務でどう使えるか" }
  ]
}
```

- `id` は英数字・`-`・`_` だけ。フォルダ名になる
- `perspective` はダイジェストに添える一言の観点。無ければ「実務でどう使えるか」

保存先が見つからなければ、対話中なら保存先を聞く。自動実行(プロンプトに `[feed-digest:auto]` がある)なら、
何もせず「保存先の設定が見つからない」とだけ出力して終える。
feeds.json が無ければ、対話中なら購読したいフィードの URL を聞いて作る。

保存先の近くに `CLAUDE.md` があれば読み、表記のルールに合わせる。

## スクリプト

`${CLAUDE_PLUGIN_ROOT}/scripts/feed.mjs`(以下 `feed.mjs`)。すべて `--root <保存先>` を付ける。

| コマンド | 役割 |
|---|---|
| `list` | 購読フィードと未ダイジェスト件数を出す |
| `fetch [--feed <id>]` | 新着を取り、`<保存先>/<id>/.feed-cache/new.json` に積む |
| `save [--feed <id>]` | チェックの付いた記事の本文を `<id>/articles/` に保存する |
| `clear-new --feed <id>` | ダイジェストを書き終えたら new.json を空にする |

`--feed` を省くと全フィードが対象。

## 手順(通常:「新着見せて」など)

フィード名を言われたらそのフィードだけ、言われなければ全フィードで行う。

1. **チェック済みを先に保存** — `node feed.mjs save --root <保存先>`
2. **新着を取る** — `node feed.mjs fetch --root <保存先>`
   失敗したフィードは理由を控えて先に進む。再試行は 1 回まで
3. **フィードごとにダイジェストを書く**(未ダイジェストが 0 件のフィードは飛ばす)
   - `<保存先>/<id>/.feed-cache/new.json` を読む
   - `<保存先>/<id>/digest/<今日の日付>.md` に書く。同じ日のファイルがあれば末尾に足す
   - 書き終えたら `node feed.mjs clear-new --root <保存先> --feed <id>`
4. **短く報告する**
   - 保存した本文の件数
   - フィードごとの新着件数と、ダイジェストのファイル
   - おすすめ度 ★3 の記事のタイトル(全体で最大 3 本)
   - 取得に失敗したフィードがあれば、その理由

## ほかの頼まれ方

- **「取得だけしておいて」** — 手順 1・2 だけ。要約は書かない。未ダイジェスト分は次回まとめて書く
  (フィードに載る件数には上限があるので、投稿の多いフィードは数日おきに取得だけしておくと取りこぼさない)
- **「チェックした記事保存して」** — 手順 1 だけ
- **「この RSS も追加して」** — URL を `fetch` できるか確かめてから feeds.json に足す。`id` と `perspective` は本人に確認する
- **自動実行(`[feed-digest:auto]`)** — 質問せずに通常の手順を最後まで行う

## ダイジェストの書式

```markdown
# <フィード名> ダイジェスト YYYY-MM-DD

## 1. <原題>
<著者> ・ <公開日時> ・ [元記事](<link>) ・ おすすめ度 ★★☆

**要約**
1. …
2. …
3. …

**<perspective>**:…(1行)

- [ ] 本文を保存（id: <id>）
```

- 公開日時の新しい順に並べる。見出しの番号は日ごとに 1 から
- チェックの行は `- [ ] 本文を保存（id: <id>）` を一字一句そのまま書く(全角かっこ。スクリプトがこの形で探す)。`<id>` は new.json の `id`
- 要約は日本語で 3 行。結論を先に書く。原文が英語でも日本語にする
- `<perspective>` の一言は、その観点で何に使えるかを具体的に。言えることが無ければ「特になし」
- おすすめ度は ★3(必読)〜★1(流し読みでよい)。基準は、perspective の観点で実務に持ち込める具体策があるか。宣伝が主の記事は ★1
- 本文に無いことを補うときは「(推測)」と付ける
- 転載記事(本文冒頭に「Originally published on」などがある)は著者の後ろに「(転載)」と付ける
- `excerptOnly` が true の記事は、要約の 1 行目の前に「※フィードは抜粋のみ」と書く。抜粋から言えることだけ要約する

## しないこと

- 記事本文をチャットに貼り出さない。本文はファイルで読んでもらう
- `.feed-cache/` の中を手で書き換えない
- 記事ページを直接開いて本文を取りに行かない(フィードにある分だけで書く)
