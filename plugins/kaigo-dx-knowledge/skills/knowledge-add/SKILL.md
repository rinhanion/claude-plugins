# knowledge-add スキル

Notionの「介護DXナレッジ」データベースに、情報を1件登録する。このデータベースが唯一のナレッジ置き場なので、新しく別のデータベースを作らない。

## 対象のNotionデータベース

- データベースURL: `https://app.notion.com/p/9c7b76d9f1a14124935baf5c5c755b1a`
- データソースURL: `collection://6744de69-f872-4a94-bc3b-19c482c15d91`

### プロパティ

| プロパティ | 型 | 入れるもの |
|---|---|---|
| `名前` | title | 内容が分かる短い題 |
| `要約` | text | 数行の要約 |
| `出典URL` | url | 取得元のURL |
| `カテゴリ` | select | `国の政策` / `自社動向` / `競合` / `業界動向` / `技術トレンド` |
| `対象企業` | select | `ベネッセスタイルケア` / `SOMPOケア` / `ニチイHD` / `ツクイ` |
| `情報の日付` | date | ページ自体が指す日付(改定日・公開日など) |
| `確認日` | date | 自分がこの情報を確認した日(今日) |

## 大前提

- Notion MCPが無い環境ではこのスキルは使えない。素直にそう伝える
- 「介護DXナレッジ」以外に新しいデータベースを作らない
- DBのプロパティ定義(選択肢の追加など)は変更しない。選択肢に当てはまらないときは該当プロパティを空にする
- 検索・振り返りや、情報源を探して複数件まとめて登録する依頼はこのスキルの範囲外。範囲外だと伝えて止まる

## 手順

### 1. 情報を集める

- URLが渡された場合: ページを取得して内容を読む。取得ツールが使えない環境では、その旨を伝えて本文の貼り付けを頼む
- 本文が貼り付けられた場合・会話で出た内容の場合: そのテキストから要約する。会話内容だけで`出典URL`が分からないときは、URLを聞く(ユーザーが「URLは無い」と答えたら空にする)

### 2. 重複を確認する

`出典URL`がある場合、データソースURLを対象に`notion-query-data-sources`で同じ`出典URL`のページを検索する。

- 見つかった場合: 新規作成せず「登録済みです」とページリンクを返して終わる。内容の更新を頼まれたときだけ、そのページの`要約`・`確認日`を更新する
- 見つからなかった場合: 次へ進む

### 3. プロパティを決める

- `名前`: 内容が分かる短い題。ページタイトルが長ければ要点だけに縮める
- `要約`: 数行。出典に書いてあることだけを書き、推測や一般論を足さない。数字・日付・制度名は出典のまま写す
- `カテゴリ`: 5つの選択肢から最も近いものを選ぶ
- `対象企業`: 内容が4社のどれかを主題にしているときだけ設定する。業界全体の話なら空にする
- `情報の日付`: ページに公開日・改定日などの記載があるときだけ設定する。記載が無ければ空にして、推測で入れない
- `確認日`: 今日の日付(Asia/Tokyo、`YYYY-MM-DD`)

`カテゴリ`や`対象企業`の判断が割れるときは、登録前に候補を挙げて一言確認する。迷わないものは確認を挟まない。

### 4. 登録する

`notion-create-pages`で、データソースURLを親にして1件作成する。日付プロパティは展開形式(`date:情報の日付:start`、`date:確認日:start`)で指定する。

### 5. 返信は簡潔に

長い説明はせず、「『〇〇』を登録しました」+ページリンク+設定した`カテゴリ`・`対象企業`程度でよい。

## やらないこと

- 出典に無い情報を要約に足すこと、`情報の日付`を推測で入れること
- 既存ページの重複作成
- DBのプロパティ定義の変更、新しいデータベースの作成
- DBの検索・振り返り、情報源の自動調査(別の依頼として扱う)
