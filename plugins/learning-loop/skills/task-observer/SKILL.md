# task-observer スキル

セッション中、次の 3 つだけを観察する。

1. **抜けていたルール** — ユーザーの修正で露呈した、スキルに書かれていなかったルール
2. **未カバーのループ** — 既存スキルがカバーしていない状況で、同じ手順を繰り返したもの
3. **効いたテクニック** — そのセッションで特に効いたやり方

観察したら `skill-observations/log.md` に追記する。修正案は `skill-updates/<日付>/<スキル名>/` にステージし、**スキル本体は直接書き換えない**。

## いつ呼ばれるか

- CLAUDE.md のルール「作業を 3 件完了するたびに task-observer を呼ぶ」による
- 「作業 1 件」は **ユーザーの依頼 1 回** と数える(コミット数ではない)。依頼に応えて報告まで終えたら 1 件と数える
- ユーザーに明示的に頼まれたとき

## 対象ファイル

プロジェクトのルート(`git rev-parse --show-toplevel`。git 管理外ならカレントディレクトリ)に置く。

- `skill-observations/log.md` — 観察ログ(追記のみ)
- `skill-updates/<YYYY-MM-DD>/<スキル名>/` — 修正案の置き場

どちらも無ければ、下の「雛形」で作る。どちらもコミットする前提のファイル(ループの材料になる)。

## 手順

### 1. 直近の作業をふりかえる

前回 task-observer を呼んでから(初回ならセッションの最初から)の会話と作業を見直す。使ったスキル、ユーザーからの訂正、繰り返した手順、うまくいったやり方を拾い、上の 3 種類のどれかに当てはまるものだけを観察として残す。

- 当てはまるものが無ければ、何も書かずに「今回は観察なし」と 1 行で伝えて終わる
- スキルに関係しないプロジェクト全般の学びは対象外(`LEARNINGS.md` の担当)。気づいたら報告で `/update-learnings` を案内するだけにする

### 2. 観察ログに追記する

`skill-observations/log.md` の表の末尾に、観察 1 件につき 1 行を追加する。既存の行は書き換えない。

| 列 | 書くもの |
|---|---|
| 日付 | `YYYY-MM-DD` |
| 対象スキル | `<プラグイン名>:<スキル名>`。2. 未カバーのループで該当スキルが無ければ `(新規) <仮のスキル名>` |
| 種別 | `1 抜けていたルール` / `2 未カバーのループ` / `3 効いたテクニック` |
| 内容 | 何が起きたか、どうすればよかったかを 1〜2 文で。Issue/PR 番号があれば添える |
| ステージ先 | 修正案を置いたディレクトリ。置かなければ `-` |

表のセル内で `|` を使わない。改行も入れない。

### 3. 修正案をステージする

スキルを直すと良くなる観察には、修正案を `skill-updates/<YYYY-MM-DD>/<スキル名>/proposal.md` に置く(同じ日・同じスキルで既にあれば、その末尾に案を追記する)。書式は下の「雛形」を使う。

修正案は次のどちらかに分類する。

- **追記型** — 既存の記述を変えず、手順・注意点・例を足すだけのもの
- **構造変更** — 既存記述の書き換え・削除、セクションの再編、frontmatter の変更、スキルの分割・統合

どちらの場合も、**スキル本体(`SKILL.md`)は一切編集しない**。

### 4. 報告する

- 追記した観察を種別ごとに短く示す
- ステージした修正案の場所と、追記型か構造変更かを示す
- **構造変更があれば**、それを明示して「反映するなら別の Issue → PR で行ってください」と伝える

## 自動でしてよいこと / してはいけないこと

| 操作 | 扱い |
|---|---|
| `skill-observations/log.md` への追記 | 確認なしで行ってよい |
| `skill-updates/` への修正案の配置 | 確認なしで行ってよい(構造変更は配置したうえで報告する) |
| スキル本体(`SKILL.md` やエージェント定義)の編集 | しない。反映は別の作業として Issue → PR で行う |
| `log.md` の既存行の書き換え・削除 | しない |
| コミット | しない。ユーザーに頼まれたときだけ行う |

## 雛形

### `skill-observations/log.md`

```markdown
# スキル観察ログ

task-observer が追記する観察の記録。既存の行は書き換えない。
種別: 1 抜けていたルール / 2 未カバーのループ / 3 効いたテクニック

| 日付 | 対象スキル | 種別 | 内容 | ステージ先 |
|---|---|---|---|---|
```

### `skill-updates/<YYYY-MM-DD>/<スキル名>/proposal.md`

```markdown
# <スキル名> の修正案(YYYY-MM-DD)

## 案 1: <短い見出し>

- 分類: 追記型 / 構造変更
- 対象: <SKILL.md のパス>(わかる範囲で。例: plugins/<プラグイン名>/skills/<スキル名>/SKILL.md)
- 根拠: skill-observations/log.md の YYYY-MM-DD の観察(<内容の要約>)

### 変更案

<足す文面、または変更前 → 変更後>
```
