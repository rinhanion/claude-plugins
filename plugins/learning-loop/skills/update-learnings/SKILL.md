# update-learnings スキル

このセッションの作業をふりかえり、新しい学び(効いた型・失敗・業務知識・覚えておく価値のある解法)を洗い出す。該当セクションに簡潔な項目として `LEARNINGS.md` を更新する。

## 対象ファイル

- プロジェクトのルート(`git rev-parse --show-toplevel`。git 管理外ならカレントディレクトリ)直下の `LEARNINGS.md`
- 無ければ、下の「雛形」で作ってから追記する

## 手順

### 1. 現状を読む

`LEARNINGS.md` を全文読む。既存の項目・書き方(言語、1項目の長さ、`(#12)` のような参照の付け方)を把握し、それに合わせて書く。

### 2. セッションをふりかえって学びを洗い出す

このセッションの会話と作業(依頼、試したこと、失敗、ユーザーからの訂正、最終的に効いた解法)を見直し、次の観点で候補を出す。

| 観点 | 入れるセクション |
|---|---|
| うまくいったやり方・型 | `Patterns That Work` |
| 失敗・ユーザーに訂正されたこと(と再発防止策) | `Mistakes to Avoid` |
| このプロジェクト固有の仕様・業務知識・覚えておく価値のある解法 | `Domain Knowledge` |
| まだ答えが出ていない問い・保留にした判断 | `Open Questions` |

`Consolidated Principles` には書かない(統合作業の出力先なので、このスキルの担当外)。

候補のふるい分け:

- **残す**: 次に同じプロジェクトで作業するとき、知っていれば時間や失敗を減らせること
- **残さない**: このセッション限りの経緯、コードや git 履歴・`CLAUDE.md` を読めばわかる事実、ユーザー個人の好み(プロジェクトを横断するものは自動メモリの担当)
- 学びが1件も無いセッションなら、無理に作らず「今回は追記する学びはありませんでした」と伝えて終わる

### 3. 重複を確認して書き込む

- 既存の項目と同じ内容なら**新しく足さない**。既存の項目に具体例や Issue/PR 番号を足して補強する
- 近い内容が別の言い回しで既にあるときも、補強を優先する
- 新しい項目は該当セクションの末尾に `- ` で始まる1項目として追加する。1項目は1〜3行で、「何が起きたか/何が効いたか」と「次にどうするか」がわかるように書く
- セクションに `(まだなし)` のような空のプレースホルダーしか無ければ、それを項目で置き換える

### 4. 総項目数を数える

追記後、`Consolidated Principles` 以外の4セクションにある項目(行頭が `- ` の行)を数える。

```bash
awk '/^## /{sec=$0; next} sec!="" && sec!~/Consolidated Principles/ && /^- /{n++} END{print n+0}' LEARNINGS.md
```

### 5. 報告する

- 追加・補強した項目を、セクションごとに短く示す
- 総項目数を伝える
- **80 件以上なら**「項目が 80 件を超えました。統合を回す時期です(Consolidated Principles への集約)」と案内する

## 雛形

`LEARNINGS.md` が無いときは、次の内容で作る(プロジェクトの会話言語が日本語なら説明文は日本語のまま)。

```markdown
# LEARNINGS.md

このプロジェクトでの作業を繰り返す中で得た学びを蓄積する記録。
セッション開始時に読み、セッション終了時に `/update-learnings` で追記する。

## Patterns That Work

(まだなし)

## Mistakes to Avoid

(まだなし)

## Domain Knowledge

(まだなし)

## Open Questions

(まだなし)

## Consolidated Principles

(まだなし。項目数が 80 件を超えたら、ここへ原則として集約する)
```

## やらないこと

- 既存の項目を削除・統合しない(統合は別の作業)
- `CLAUDE.md` や自動メモリ(`~/.claude/memory/`)は書き換えない
- コミットはしない。ユーザーに頼まれたときだけ行う
