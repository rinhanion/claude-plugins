# note-draft スキル

`hiroking22` の過去記事から抽出した文体プロファイルに沿って、note の下書き記事を Markdown で生成する。
確認が取れたら note-api MCP の `post-draft-note` で下書き投稿する（公開まではしない）。

## 大前提

- **文体の根拠はこのスキルに同梱された `STYLE.md`（このファイルと同じディレクトリ）だけ**。書き始める前に必ず読む。
- 生成するのは常に「下書き」。**自動で公開しない**。投稿も、本文をユーザーに見せて明示的なOKをもらってから。
- **体験・レポート系で、本人が言っていない事実・セリフ・数字・固有名詞を創作しない**。埋められない箇所は本文に `（★確認）` を残し、生成後にまとめて質問する。

## 手順

### 1. ネタを集める

入力は2パターン。

**(a) ユーザーがトピック / メモ / 会話の内容を渡してきた場合**
そのまま材料にする。足りない情報（時系列、登場人物の呼び方、実際の発言、伝えたいこと）は、書く前に軽く1〜2問だけ聞く。根掘り葉掘り尋問しない。

**(b) 「ネタ帳から」と言われた / ネタ帳のストックを起点にしたい場合**
ネタ帳はこのスキルの中には無い。置き場の場所はユーザーレベルの設定に書かれている。

- 探し先: `~/.claude/CLAUDE.md`(そこから `@` で読み込まれるファイルを含む)、開いているフォルダの `CLAUDE.md`
- 書き方の例: `- ブログのネタ帳の置き場: <フォルダのパス>`
- 置き場の近くに `CLAUDE.md` があれば読み、書き方のルールに合わせる

ネタ帳は 1 ネタ 1 ファイルの Markdown。frontmatter は `種類: ブログネタ` / `ステータス`(ストック・執筆中・公開済み) / `カテゴリ`(技術・プライベート・どちらでも) / `note URL` / `作成日`。ファイル名がネタのタイトル。

1. `ステータス` が `ストック` または `執筆中` のファイルを、作成日の新しい順に一覧で見せて、どれを書くか選んでもらう
2. 選ばれたファイルの本文(本人が書いたラフや箇条書き、元ニュースのメモ)を材料にする
3. 設定が見つからない、または置き場のファイルを読めない環境なら、この経路はスキップして (a) に倒す(「ネタ帳を読めない環境なので、ネタの中身を貼ってください」)

### 2. 記事タイプを決める

`STYLE.md` の「5. 記事タイプ別テンプレート」から近いものを選ぶ（技術いじり / 週次ふりかえり / イベントレポート / 本の感想 / 調べもの / 練習ログ）。どれにも当てはまらなければ、いちばん近い型をベースに崩す。ユーザーがトーンを指定していれば（例: 「ニュートラルで」）それを優先。

### 3. 本文を書く

`STYLE.md` の「1. 声のルール」「2. 構成の型」「3. 表記のクセ」「6. アンチパターン」に従って、Markdown で本文を書く。

- 冒頭は動機・背景から
- `##` で場面転換、段落は短く、思考の区切りで改行
- 締めは「というわけで、〜でした。」＋感謝／前向きな一文の型
- 絵文字は山場だけ。硬い書き出し・一般論の羅列をしない
- 本人の具体（固有名詞・数字・その時の気持ち）を必ず入れる。無ければ `（★確認）`
- 固有名詞は `STYLE.md` の「7.」を参照して間違えない。健康（バセドウ病）の話は、本人がその記事で書くと決めたときだけ。他記事へ勝手に持ち込まない

### 4. 見せて確認する

生成物をユーザーに提示する:

- **タイトル案を3つ**（`STYLE.md` の「4. タイトルの型」に沿って）
- **本文ドラフト**（Markdown）
- `（★確認）` で残した未確定点の一覧と質問

ユーザーの修正を受けて直す。ここで OK が出るまで投稿しない。

### 5. 下書き投稿（任意）

ユーザーが「投稿して」「下書きにして」と言ったら:

- **note-api MCP がある場合**: `mcp__note-api__post-draft-note` を呼ぶ（`title` / `body`(Markdown) / 必要なら `tags`）。投稿後、返ってきた編集URLを伝える。
  - 注意: このMCPには下書き削除ツールが無い。投稿は確定版で行う旨を、投稿前にひとこと確認する。
- **note-api MCP が無い場合**: 最終Markdownをコードブロックで出力し、「note編集画面に貼り付けてください」と伝える。

### 6. ネタ帳に書き戻す(ネタ帳起点のとき)

(b) の経路で書いた場合、完了時に元のネタ帳ファイルを更新する:

- 本文の末尾に `## 下書き` の見出しで、生成した本文(または note の下書きURL)を追記
- `ステータス` を `執筆中` に(まだ公開前)／ note で公開されたら `公開済み` に、`note URL` も設定
- 既存の本文は消さない。迷ったらユーザーに一言確認してから更新する

## やらないこと

- 記事の自動公開
- `STYLE.md` を無視した「一般的にいい感じの記事」の生成
- 文体プロファイルの自動書き換え（`STYLE.md` の更新はリポジトリで手動）
- 体験談の脚色・事実の創作
