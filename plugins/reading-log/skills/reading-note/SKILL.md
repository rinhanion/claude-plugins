# reading-note スキル

Notionの「読書リスト」データベースで読書中のページに、会話から生まれた気づきや感想を「読書メモ」として本文に追記する。このデータベースが唯一の読書リストなので、新しく別のデータベースを作らない。

## 対象のNotionデータベース

- データベースURL: `https://app.notion.com/p/ce509cc158de4cb6a29edd9da00f3cc3`
- データソースURL: `collection://3821c5b6-1c46-41f1-a6c7-7ae1d56a64bf`
- 触るのはページ本文(コンテンツ)のみ。`ステータス`・`読み始め`・`読了`などのプロパティには触れない

## 大前提

- Notion MCPが無い環境ではこのスキルは使えない。素直にそう伝える
- 読書開始(`ステータス`を`読んでる`にする)の記録はこのスキルの範囲外。`reading-start`スキルの仕事
- 追記するのはページ本文の「## 読書メモ」セクションのみ。プロパティは一切変更しない
- 「読書リスト」以外に新しいデータベースを作らない

## 手順

### 1. 対象の本を特定する

`notion-query-data-sources`(rowsモードまたはSQLモード、対象は上記のデータソースURL)で、`ステータス`が`読んでる`のページを検索する。

- 1件だけ見つかった場合: それを対象にする
- 複数見つかった場合: どの本のことか一言で確認する(候補のタイトルを挙げてよい)
- 0件の場合: 「読んでる」状態の本が無い旨を伝え、どの本のことか聞く

### 2. 直前の会話を要約する

この会話でユーザーが話した内容から、次の2つを切り出す。

- **つぶやき**: ユーザーが話した気づき・疑問・感想。言い回しやニュアンスを保つ。短縮しすぎて
  ユーザーの言葉が失われないようにする(「〜と思った」を「〜」にするような過度な圧縮はしない)
- **コメント**: それに対してClaudeが返した補足情報・関連知識・答えなど。冗長な前置きは削り、
  要点を箇条書きにする。1〜2行で済む内容なら箇条書き1つでよい

会話の中に該当するやり取りが複数ある(複数の話題を話した)場合は、直近のひとまとまりを対象にする。どこまでを対象にすべきか曖昧なら一言確認する。

### 3. ページ本文に追記する

対象ページの本文(コンテンツ)を確認し、"## 読書メモ" という見出しが無ければページ末尾に新規作成し、既にあればそのセクションの末尾に追記する。追記するブロックのフォーマットは次の通り(日付はAsia/Tokyoでの今日の日付、`YYYY-MM-DD`):

```
### {YYYY-MM-DD}

> 🗣️ {ユーザーのつぶやき}

**💬 Claude**
- {Claudeの補足コメント、箇条書き}
```

- `notion-fetch`などでページ本文の現状を確認してから、`notion-update-page`で本文ブロックを追記する
- 既存の本文やプロパティを壊さないよう、追記対象以外のブロックには触れない

### 4. 返信は簡潔に

長い説明はせず、「『〇〇』の読書メモに追記しました」+ページリンク程度でよい。

## やらないこと

- `ステータス`・`読み始め`・`読了`など、本文以外のプロパティを変更すること
- 読書開始・読了の記録(それぞれ別スキルの範囲)
- ユーザーのつぶやきを要約しすぎて言葉のニュアンスを失うこと
- 「読書リスト」以外に新しいデータベースを作ること
