# reading-start スキル

Notionの「読書リスト」データベースに読書開始を記録する。このデータベースが唯一の読書リストなので、新しく別のデータベースを作らない。

## 対象のNotionデータベース

- データベースURL: `https://app.notion.com/p/ce509cc158de4cb6a29edd9da00f3cc3`
- データソースURL: `collection://3821c5b6-1c46-41f1-a6c7-7ae1d56a64bf`
- 使うプロパティ: `タイトル`(title) / `ステータス`(select: 読みたい・読んでる・読了) / `読み始め`(date) / `著者`(multi_select) / `出版社`(select) / `一言メモ`(text)
- 上記以外のプロパティ(`タグ`・`入手手段`・`再読したい`・`評価`・`購入価格`・`表紙`・`URL`など)には触れない。ユーザーが明示的に言及したときだけ埋める

## 大前提

- Notion MCPが無い環境ではこのスキルは使えない。素直にそう伝える
- ステータスの選択肢は `読みたい` / `読んでる` / `読了` の3つのみ。存在しない値を使わない
- 読了(読み終わった)の記録はこのスキルの範囲外。ステータスを `読了` にしたり `読了` プロパティ(date)を触ったりしない

## 手順

### 1. 本のタイトルを確認する

- メッセージにタイトルが含まれていればそれを使う
- 含まれていなければ、どの本を読み始めるか一言で聞く(長い質問攻めにはしない)

### 2. 「読書リスト」データベースを検索する

`notion-query-data-sources`(rowsモードまたはSQLモード、対象は上記のデータソースURL)や `notion-search` で、`タイトル` が一致・部分一致するページを探す。

完全一致しなくても、表記ゆれ(サブタイトルの有無・全角半角など)や部分一致で近いものがあれば候補として提示してよい。誤って別の本を更新しないよう、候補が複数・曖昧な場合は必ずユーザーに確認する。

### 3. 見つかった場合

- 既存ページの `ステータス` を `読んでる` に更新する
- `読み始め` プロパティ(date)を今日の日付(Asia/Tokyoの「今日」)に設定する。`date:読み始め:start` に日付のみを入れ、`date:読み始め:is_datetime` は `0`(時刻は付けない)
- すでに `ステータス` が `読んでる` になっている場合は、上書きする前に読み始め日を更新していいか一言確認する
- `ステータス` が `読了` になっている場合は、再読として扱ってよいか確認してから更新する
- 更新できたら、ページへのリンクとともに短く報告する

### 4. 見つからなかった場合

- リストに登録されていない旨を伝え、新規ページとして追加してよいか確認する
- OKなら `notion-create-pages` でデータソース(`collection://3821c5b6-1c46-41f1-a6c7-7ae1d56a64bf`)配下に新規ページを作成する
  - `タイトル`: 伝えられた本のタイトル
  - `ステータス`: `読んでる`
  - `date:読み始め:start`: 今日の日付、`date:読み始め:is_datetime`: `0`
  - 著者・出版社などユーザーが自然に言及していれば `著者`(multi_select)・`出版社`(select)に入れてよいが、無理に聞き出さない。DBの選択肢に無い値でも新しい選択肢として追加される

### 5. 返信は簡潔に

長い説明はせず、「『〇〇』を読んでる中にして、読み始めを今日にしました」+ページリンク程度でよい。

## やらないこと

- 読了記録(`ステータス`を `読了` にする・`読了` 日を設定する)
- 存在しない選択肢での更新
- 表記ゆれ・複数候補があるまま確認なしで更新すること
- 「読書リスト」以外に新しいデータベースを作ること
