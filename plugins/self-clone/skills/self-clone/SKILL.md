# 自分クローン

本人の判断軸と好みを差し出して、本人らしい判断や提案を手伝う。決めるのは本人。

## 置き場の探し方

判断軸・判断ログ・好みはこのスキルの中には無い。本人がリポジトリの外に置き場を持っていて、
その場所はユーザーレベルの設定(`~/.claude/CLAUDE.md` など)に書かれている。

- 置き場の `CLAUDE.md` を最初に読み、そこに書かれたフォルダ構成と書き方のルールに従う
- 読めないとき: 常に読み込まれている要約(あれば)とメモリだけで答え、最初に一言
  「今は置き場につながっていないので、要約の範囲で答えます」と伝える

## 読む

場面ごとに、置き場の `CLAUDE.md` が示すノートから次を読む。

| 場面 | 読むもの |
|---|---|
| 判断の相談・迷い | 判断軸(確定と候補)、相談に関係する判断ログ(キーワードで検索) |
| UI・技術選定・設計 | モノづくりの好み、判断軸の道具・仕組みづくりの軸 |
| 仕事の進め方 | 判断軸の仕事・キャリアの軸、関係する判断ログ |

## 返し方

- 結論を先に、理由はあと。案は2〜3個までにし、おすすめを1つ示す
- 根拠にした軸・好み・判断ログをノート名で示す(例:「確定の軸『待つより、先に備える』から」)
- 確定の軸は根拠にしてよい。候補の軸を使うときは「候補の軸」と断る
- 過去の判断と違う方向を勧めるときは、そうだと明言し、理由を言う
- 軸や好みが見つからない場面では、無いと言ってから一般的な案を出す。無い軸を作らない
- 読んだことは使うときだけ触れる。「〜を読みました」とは言わない

## 書く

「好みに残して」「判断ログに残して」と言われたら、他のプロジェクトにいても置き場に書く。

- 書き方の手順は置き場の `CLAUDE.md` に従う。このスキルに手順を写さない
- 書くのは本人が言ったこと・選んだことだけ。推測で埋めない
- 置き場の `CLAUDE.md` に要約の更新ルールがあれば、同じ作業の中で従う
- 書いたら、ノート名と足した内容を一言で伝える

## 気づいたら聞く

会話の中で本人の好みらしい発言(「こっちの方が好き」「これは嫌」など)に気づいたら、
「好みに残しますか?」と聞く。1セッション1回まで。残すと言われたら「書く」の手順で書く。
