# session-neta スキル

`~/blog-neta/sessions/` に溜まった**セッションのネタ帳**を扱う。ネタ帳は SessionEnd フックが
自動生成した Markdown で、Claude Code の1セッションぶんの作業内容（何をやろうとして、何を触って、
どこで詰まったか）が入っている。

このスキルの役割は **ネタ帳を選んで、記事に必要な文脈を補い、`note-draft` に渡すまで**。
記事の本文を書くのは `note-draft` スキル（文体プロファイル `STYLE.md` を持っている方）の仕事で、
こちらで文体を再定義したり STYLE.md を複製したりしない。

## 大前提

- **ネタ帳には「何をしたか」しか入っていない**。記事に必要な「なぜやったか」「そのときどう思ったか」
  は本人の頭の中にしかないので、書き始める前に必ず聞く。
- ネタ帳に無い数字・エラーメッセージ・所要時間を**創作しない**。
- **自動で公開しない**。note への下書き投稿も、本文を見せて OK をもらってから。

## 1. ネタ帳の在庫を見せる

`~/blog-neta/sessions/`（`BLOG_NETA_DIR` が設定されていればそちら）のファイルを新しい順に読む。
各ファイルの YAML front matter（`title` / `date` / `project` / `prompts` / `files_changed` /
`status`）を拾って、表で見せる。

```
| 日付 | プロジェクト | タイトル | 会話 | ファイル |
```

- デフォルトでは `status: ネタ`（＝まだ記事にしていない）を優先して見せる。直近10件くらいでよい。
- `status: 公開済み` は「書いたやつ」として畳んでおき、聞かれたら出す。
- ディレクトリが空／存在しない場合は、まだ SessionEnd が回っていないだけなので、
  そう伝えて 2. の「今のセッション」経路を案内する。

ユーザーが「一覧見せて」で止まるならここで終わってよい。無理に記事化へ進めない。

## 2. 今のセッションをネタにしたい場合

「今日やったこと」「さっきの作業」と言われた場合、そのセッションはまだ終わっていないので
ネタ帳が存在しない。その場でハーベスタを直接叩いて作る:

```sh
node "${CLAUDE_PLUGIN_ROOT}/scripts/harvest.mjs" --transcript <現在のトランスクリプトのパス>
```

トランスクリプトは `~/.claude/projects/<cwd をハイフン化したもの>/<session_id>.jsonl`。
どれか分からなければ、そのプロジェクトのディレクトリで**更新時刻が最新の `.jsonl`** を使う:

```sh
ls -t ~/.claude/projects/-Users-rinkoro-projects-<プロジェクト名>/*.jsonl | head -1
```

生成されたファイルのパスが標準出力に出るので、それを読む。
（中身が薄いと判定されると何も出力されない。その場合は「まだ記事にするほどの作業がない」と伝える）

## 3. 足りない文脈を聞く

選んだネタ帳を読み、**1〜2問だけ**聞く。尋問しない。ネタ帳から読み取れることは聞かない。

聞くべきなのはたいていこの2つ:

- **なぜそれをやろうと思ったのか**（何が不便だった／気になっていたのか）
- **やってみてどうだったか**（詰まったところの気分、うまくいったときの手応え、次にやりたいこと）

ネタ帳の「つまずき・エラー」に中身がある場合は、そこが記事の山場になるので
「ここで詰まってるけど、何が原因だった？」と具体的に聞くとよい。

## 4. note-draft に渡して記事化する

`note-draft` スキルを使って本文を生成する。渡す材料:

- ネタ帳の中身（やろうとしたこと／会話の流れ／触ったファイル／つまずき／git）
- 3. で聞き出した「なぜ」と「どう思ったか」

記事タイプは `STYLE.md` の **「A. 技術・ツールいじり」** を基本にする（動機 → やってみる →
詰まる → 解決、の流れがネタ帳の構造とそのまま噛み合う）。週の作業をまとめて1本にする場合は
「B. 週次ふりかえり」に寄せる。

タイトル案は3つ出して選んでもらう。`（★確認）` が残っていればまとめて質問する。

## 5. 書いたら記録を残す

note に下書き投稿できたら、元のネタ帳の front matter を更新する:

```yaml
status: 公開済み      # 下書き投稿しただけなら 執筆中
note_url: "https://note.com/..."
```

これで次に一覧を出したとき、書いたものと未着手が区別できる。

## やらないこと

- 記事の自動公開、確認なしの下書き投稿
- ネタ帳に無い事実（エラー文・数字・所要時間）の創作
- `STYLE.md` の複製や、独自の文体ルールの定義（文体の根拠は note-draft の STYLE.md だけ）
- ネタ帳ファイルの削除（書き終わっても `status` を変えるだけで残す）
